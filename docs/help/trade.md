# 交易、人脉、服务与委托

交易观察、通用面板与对白入口已接入。单件／批发购入、电话和展示柜升级有迁移前实机证据；易物、议价、卖出、电脑委托等仍未全面验收。

## 柜台交易

1. get_trade_state 查看 customer、trade、interaction、controls 和 availableActions。
2. trade.direction 是玩家视角：player_buys 表示玩家付款收购，player_sells 表示玩家收款出售。
3. 需要摆货时使用当前 item_move；重新读取报价、拒收原因和数量。
4. 使用当前原生交易／议价／确认面板动作，遵循其参数和限制。
5. 成交后核对现金、物品归属、库存和 businessComplete。dismiss_customer 只是送客，不表示成交。

quotes[].amount 是整件／整堆当前报价，不要再乘 count。wholesale_total 可能包括柜台以外的顾客货物，不与逐件报价相加。特殊业务可能没有现金报价，应读取可见条款。public_claim 属性不等于鉴定为真。

## 电话、人脉与服务

使用可见电话和面板动作，按当前字段输入号码、选择对白。人脉卡片的 ui_select_upgrade 打开升级详情，不等于已经购买；核对前置、费用和确认，购买后检查实际变化。服务启停要确认勾选状态和结算费用。

## 电脑与委托

读取面板中的商品、数量、期限和报酬，再通过原生交货与确认操作。不能假定游戏自动交货时会挑哪件物品，也不能仅凭按钮 dispatched 宣称任务完成。界面未暴露动作时报告缺口；不构造专用命令。
