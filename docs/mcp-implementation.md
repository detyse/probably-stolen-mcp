参数由 `availableActions[].parameters` 给出，而不是把全部游戏操作编码成固定工具名。每个动态动作带 `kind`、`targetId` 和本次合法参数。机器、电话、电脑、夜间菜单等复用这些控件入口；游戏回调负责配方、花费、解锁、交货和剧情后果。

## 调用示例

先读取 `get_available_actions`。下面的引用仅为格式示例，实际使用时必须替换为返回的完整动作名、候选引用和快照。

```json
{
  "action": "item_move:e<session>_<item>",
  "expectedSnapshotId": "<当前 snapshotId>",
  "requestId": "<新 UUID>",
  "arguments": {
    "destinationId": "<parameters 中列出的容器引用>",
    "quantity": 2,
    "x": 3,
    "y": 1,
    "rotation": 1,
    "flipped": false
  }
}
```

省略 `x/y` 时由游戏自动选位置；指定位置时 `x/y` 必须同时给出。`rotation` 为游戏的 0–3 四分之一转朝向。数量默认当前整堆，显式数量必须整份容纳才发起转移。自动拆分会重新校验，避免拆出的物品与原堆叠重叠。原生回调异常或实际数量不符时返回结果不确定，不尝试回滚。

滑条传 `value`，范围滑条同时传 `value`、`upperValue`；切换开关／固定物品传 `toggle`；文本传 `text`；选项或标签页传 `index`；工具作用于目标传 `targetId`。每次仍须以该动作的参数表为准。未知字段、缺少必需参数、非法候选、越界或步长不符会被拒绝。

`get_inventory(containerId?, offset=0, limit=100)` 的 `limit` 为 1–200，返回总数及容器摘要。`inventory` 是已呈现容器的直接内容，不是全局资产表；物品动作要求物品已呈现，并满足原生 May/Can、所有权、锁定和槽位条件，不以屏幕射线作为业务操作前提。嵌套容器只在已打开后出现。容器 `label` 提供可见设备面板名称或插槽提示（可为空），`role` 区分库存、展示柜、柜台、垃圾桶、地面、口袋和背包；`parentItemId` 对应嵌套物品。格子 `cells` 用 `#` 表示原生值 1、`.` 表示其他值：物品里通常是占据格，库存里对应不可用格；不要仅按矩形尺寸判断可放置性。

`get_action_status` 返回最初保存的结果，所附 `state` 也是当时的观察。`dispatched` 只说明调用已发出；没有为每类交易、动画、长按和生产实现独立的完成事件跟踪。应重新读取局面并核对实际变化。未找到 UUID 不证明未执行，记录仅保留最近 256 条且 Mod 重启后清空。

## 验证与边界

自动测试使用生产 HTTP 服务、真实 MCP 服务进程及官方 MCP 客户端，游戏对象由测试替身提供。覆盖参数传递与拒绝、UUID 参数冲突、跨会话失效、动作状态查询、实体查找、库存分页、图片传输、身份校验、报文限制和超时。这些测试不运行 Unity，也不能验证原生交易、形状、视觉遮挡、长按、文字校验或截图内容是否与游戏一致。

原生适配已针对本机程序集编译。实现过程中只读核对了 UI、物品转移和输入处理器；相关工作材料留在忽略的 `.cache/research/`，不分发游戏代码或 DLL。

明确限制：没有任意坐标／任意按键或反射调用；只支持列出的控件类型；视图采样未做全部分辨率和画布层级验收；公开文字快照最多 256 段、每段最多 4096 字符；没有所有专用机器的独立配方／进度模型；没有原子多件事务。被遮挡或不支持的输入应通过当前窗口流程解决，无法发现时需要补适配，不能强行调用底层修改方法。

2026-11-07 迁移时通过 128 项自动检查，新增内置帮助后完整套件通过 151 项检查。一天经营及扩展实机证据来自迁移前构建，更名后的 Mod 尚未重跑完整流程；结果见 [能力清单](capabilities.md) 与其证据索引。尚未验收的交易方向、议价、鉴定、生产和夜间地点继续保留未实测状态，不能将 132 个交互族标记为全部验证。
