## 状态怎么读

- **已接入**：仓库已有读取或原生执行入口。
- **通用入口已接入**：通过可见 UI 操作；具体玩法／控件仍需现场确认。
- **已实测**：必须有真实游戏中的版本、步骤、调用和结果记录。编译、测试替身或成功列出 MCP 工具均不能代替。
- **未实测**：本清单尚无足够证据标记为实机通过，并不表示已经验证失败。
- **未支持**：当前没有相应入口。

迁移前通过官方 MCP 客户端连接真实 MCP 服务与已加载 Mod，完成一天经营及下列扩展实测。使用用户提供的第 1 天、700 信用点存档；原始存档已本地备份。没有修改现金、天数、归属或隐藏身份来构造结果。

## Agent 如何通过 MCP 验货与鉴定

Agent 可以通过 MCP 自己完成观察、使用工具、判断和提交。MCP 提供状态、图片与原生操作入口；选择工具、比较线索、判断真假或估价由 Agent 完成。目前没有一键返回未揭示真假或正确估价的鉴定工具，也没有内置的完整鉴定策略。

| 步骤 | MCP 调用 | Agent 做什么 |
| --- | --- | --- |
| 观察物品与工具 | `get_game_state`；需要分页时用 `get_inventory` | 找到目标物品、已拥有的放大镜／检测工具及当前可用动作；区分 `public_claim` 和 `revealed` |
| 确认可用检测入口 | `get_available_actions` | 找到工具对应的完整 `item_use_on:<引用>`，检查 `parameters` 中 `targetId` 的合法候选；也可能使用当前列出的物品查看／激活动作 |
| 使用工具 | `perform_action` | 把合法物品引用作为 `arguments.targetId` 提交；由游戏正常执行检查、检测与耗材消耗 |
| 读取证据 | `get_ui_state`、`get_view` | 读取面板、检测数值和 MCP 返回的游戏图片；视觉 Agent 根据图案／外观及可访问的游戏手册判断。纯文本 Agent 对只有图像的线索能力有限 |
| 提交判断或估价 | `perform_action` | 根据新观察使用面板的完整按钮动作；若存在估价输入框，按该动作参数传入 `text`，再重新观察并点击提交。只使用实际出现的动作 |
| 核对结果 | `get_game_state`、`get_ui_state`，需要时 `get_view` | 检查界面反馈、已揭示属性、评级或报酬；一次 `dispatched` 不代表整套鉴定已完成 |

以下是调用 MCP 工具 `perform_action` 的**参数模板**。所有占位符必须替换为当次观察的真实值，不是可直接执行的命令：

```json
{
  "action": "<复制工具对应的完整 item_use_on 动作名>",
  "expectedSnapshotId": "<最新观察的 snapshotId>",
  "requestId": "<新 UUID>",
  "arguments": {
    "targetId": "<该动作 parameters 中允许的目标物品引用>"
  }
}
```

工具作用于目标不保证直接返回真假：有的检查呈现图案，有的检测呈现数值，也可能由游戏明确揭示某个结论。Agent 使用这些玩家可见证据；交易报价不等于正确估价。上述操作入口已接入，水质试纸和净水已有实测；各品类的完整鉴定流程仍未实测。

## 明确未支持的能力

| 能力 | 状态／替代路径 |
| --- | --- |
| 任意屏幕坐标点击、任意按键、任意鼠标拖拽 | 未支持；使用列出的原生动作，物品移动使用结构化位置参数 |
| 任意反射调用或直接修改现金、归属、天数、身体状态 | 未支持 |
| 导出未揭示真假、真实价值、NPC 隐藏身份或未来事件 | 未支持；公开声称的属性仍可能不真实 |
| 读取所有资产、未打开容器的内部内容 | 未支持；先通过正常流程打开可访问容器 |
| 一键完成选人开局、一天经营、全部交易或生产 | 未支持；按当前界面逐步操作，不能把共用入口当成流程已经完成 |
| 原子多件操作、全局回滚 | 未支持；逐件提交并检查结果 |
| 强制解锁、跳过确认／动画、直接完成生产 | 未支持；遵循游戏当前规则与等待状态 |
| 未适配的自定义控件、被禁用或遮挡的控件 | 当前无法执行；缺少动作时需检查正常界面流程或补适配 |

## 运行时如何确认某个按钮现在能用

客户端读取 Mod 返回的 `availableActions` 即可；原生 Can/May、经营阶段、所有权、容量、锁和特殊界面状态由适配层统一检查，执行前再次验证。业务命令（如物品转移、睡眠）不依赖鼠标坐标；普通 UI 按钮仍需遵守遮挡与原生可交互状态。原生游戏没有统一的全玩法“可操作列表”，自定义目的地／升级卡片和只在回调内检查条件的拾荒按钮需要适配，但不用由每个 MCP 客户端逐页维护。

1. 调用 `get_bridge_status` 确认连接，再用 `get_ui_state` 获取 `snapshotId`、可见文字、`controls` 与 `availableActions`。视觉线索用 `get_view` 补充；截图也会采样，执行前使用最新观察重新判断。
2. 找到目标控件，核对 `enabled`、`disabledReason` 和 `actions`。`get_available_actions` 可单独查询完整动作及参数范围。
3. 只把本次返回的完整动作名交给 `perform_action`，携带当前 `expectedSnapshotId` 和新 UUID `requestId`，参数按该动作的 `parameters` 填写。`ui_click:<引用>` 等仅表示命名格式，不能自行拼接引用。
4. 操作后重新读取界面或截图，核对选中状态、说明、点数、下一页或进入店铺等实际变化。`dispatched` 只证明处理函数已调用，不能单凭它判定流程成功。
5. 若返回 `stale_snapshot`，重新观察、决定并使用新 UUID。超时或断线时先用 `get_action_status` 查询；重试同一命令必须保留原 UUID、动作名、快照和全部参数。

只有文字或截图、没有对应动作时，不能认定按钮可控制。空动作列表也不能直接认定页面永远不支持：可能正在加载、长按、被遮挡／禁用，或控件尚未适配。先结合当前画面与等待状态判断。
