## 本轮修复

- **职业、难度、特性卡片漏识别**：这些卡片复用了升级界面的指针组件，原实现只在升级页采集。现在按原生菜单类型读取选中状态和锁定状态，并执行原生指针回调。特性从菜单目录读取，避免菜单观察意外创建店铺状态。
- **游戏内后退入口缺失**：新增当前可用时才出现的 `navigate_back`。它调用原生后退处理，先关闭顶部窗口或选择，再打开暂停菜单；暂停中也可返回。
- **返主菜单后状态查询报错**：识别实际主菜单控制器，并在调用窗口方法前检查 Unity 对象是否仍有效，避免残留窗口引用使观察持续失败。连续多职业往返已回归。
- **设备容器缺少名称**：新增 `containers[].label`，读取可见设备面板标题或插槽提示。已核对“输入、输出、种子输入、水箱、动物、模组”等。只有图标的槽位仍可能为空，应结合父物品、窗口和合法目标判断。

本轮没有改写游戏物品规则。试纸保留为已用物品、满水瓶不能补水、刀具分两步处理动物等，都按实际游戏结果修正了测试预期。

## 证据与存档

证据包含 203 次记录的动作提交：200 次已发送、2 次合法性拒绝、1 次早期候选异常。异常来自开发中的特性查询，已修复并回归；这些数量不代表 203 个独立功能全部成功。另有 75 项通过的状态断言和 4 项已解释、纠正的测试预期。真实加工完成与 `dispatched` 分开判断。

原有槽位 0、1 及其 5 个日备份共 7 个存档文件，与测试前备份的 SHA-256 完全一致。新建测试槽位为 2–11，测试结束停在主菜单；没有开启开发工具或直接编辑游戏／存档数值。完整本地记录和备份位于被忽略的 `.cache/profession-tests/`，不随仓库分发。

本轮覆盖职业物品与开局／返回流程，**没有重新跑完整开店、交易、闭店、睡觉链路**。跨夜生产、全部物品、其他游戏 Build 和分辨率仍须另测。

最终构建 **0 警告、0 错误，152 项自动检查全部通过**；发布后的 MCP 服务也在实机中通过了 get_inventory 与 get_entity 的设备标签回归。
